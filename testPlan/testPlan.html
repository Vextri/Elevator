Test Plan for the Elevator Project

Test Objectives and Scope

The purpose of testing the Project's VI elevator is to confirm CAN, Ethernet, and Wireless communication with the Raspberry Pi. The testing will verify that all components can successfully communicate with each other and exchange data as expected.

Test Types

Communications Testing and Verification

  • CANBus
  • Wireless

Functional Testing

  • Database
  • Height Sensor
  • Speed

Additional Features

  • Card Reader
  • Diagnostics

Test Procedures

CANBus

Transmission of CAN Messages

Objective: Verify that the supervisory controller can transmit CAN messages to itself, MCUs, and Arduino.
Procedure: 
Program the supervisory controller to send messages on the CAN bus.
Verify that messages are received by the intended recipients (itself, MCUs, Arduino).
Ensure that payloads are correctly formatted and as expected.

Listening for CAN Messages (Message Filtering)

Objective: Ensure that the supervisory controller correctly listens for messages and filters out unnecessary traffic.
Procedure: 
Set up a specific MCU to periodically broadcast messages on the CAN bus.
Verify that only the supervisory controller is receiving the messages (filters are working correctly).
Monitor and log message activity to verify the CAN bus is correctly receiving and processing.

Message Payload Verification

Objective: Verify the integrity and correctness of payloads within the messages.
Procedure: 
The supervisory controller should read and decode the payloads from messages on the CAN bus.
Check for correctness in the payload data for different types of messages (move floors, control signals, etc.).

Wireless

Wireless Communication Setup

Objective: Ensure proper setup of the wireless communication (Wi-Fi, Bluetooth, etc.) between the supervisory controller and external devices.
Procedure: 
Set up the wireless module on both the supervisory controller and any external devices (e.g., Arduino, MCU).
Verify successful connection between devices via the wireless network.

Wireless Communication Stability

Objective: Verify the reliability of wireless communication.
Procedure: 
Test message transmission under various conditions (e.g., interference, distance).
Measure latency, packet loss, and data throughput over the wireless link.

Website Controller Integration

Objective: Test communication between the supervisory controller and the website interface.
Procedure: 
Use the website to control supervisory controller features.
Monitor Ethernet communication for performance and correctness.
Verify that the website can send and receive valid commands.

Database

Database Connection and Data Integrity

Objective: Ensure that the database correctly stores and retrieves data related to elevator operations.
Procedure: 
Test the database connection by performing read and write operations.
Verify that data is correctly stored and can be retrieved without errors.
Check for data integrity and consistency across different operations.

Handling of Floor Requests

Objective: Ensure that the system correctly handles floor requests from users.
Procedure: 
Simulate floor requests from the website interface.
Verify that the database stores multiple values in the floor request column.
Check that the correct commands are sent to the elevator controllers.
Check that current floor is updated correctly in the database.

Height Sensor

Height Sensor Functionality

Objective: Verify that the height sensors correctly measure the elevator's position.
Procedure: 
Test the height sensors by moving the elevator to different floors.
Verify that the sensors accurately report the current height.
Check that set points are somewhat accurate.

Height Sensor Data Logging

Objective: Ensure that height sensor data is logged correctly in JSON file for diagnostics.
Procedure: 
Verify that the height sensor data is logged in a JSON file.
Check that the data includes a timestamp and 30 height values for each floor.

Speed

Elevator Motor Speed

Objective: Adjust the elevator motor speed to ensure smooth operation.
Procedure: 
Test the elevator motor speed by moving the elevator between floors.
Adjust the damper settings to ensure smooth operation.    
Verify that the elevator does not over-shoot the target floor.

Card Reader

Card Reader Functionality

Objective: Verify that the card reader correctly reads and processes user cards.
Procedure: 
Test the card reader by scanning different user cards.
Verify that the reader correctly identifies the user and grants access to the elevator.

Diagnostics

Diagnostics Functionality

Objective: Ensure that the diagnostics feature correctly logs and displays elevator data.
Procedure: 
Test the diagnostics feature by running the diagnostics section of "main.cpp".
Verify that the diagnostics page displays the correct height data for each floor.
Display setpoint with other collected data.
